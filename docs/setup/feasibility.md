# Mac mini での実現性とデータセットの選定

調査日: 2026-10-29。対象: Transolver（ICML 2024）、Mac mini（Apple M5 Pro、メモリ24GB）、PyTorch MPS。

この時点では文献と公式リポジトリの構成に基づく見込みで、実際の学習・推論は行っていない。

## 結論

- AirfRANS で Transolver を学習・推論すること自体は Mac mini で可能と見込む。論文と同じ規模の学習をそのまま再現するのは重いので、縮小した設定から始める。
- 形状と気流条件の両方を変えた流れ場予測には AirfRANS が最も合う。

## Mac mini で動かせるか

| 項目 | 見込み |
|---|---|
| 演算 | Physics-Attention はほぼ素の PyTorch 演算（einsum、softmax、Linear）なので MPS で動く |
| メモリ | 計算量は節点数に線形。AirfRANS の1ケース（約18万節点）の推論は24GBで足りる。統合メモリはOSや前処理と共有なので、学習に使えるのはおよそ16〜18GB |
| 時間 | A100 クラスより数倍以上遅いと見込む。論文の設定（全800ケース × 数百エポック）だと数日かかる可能性がある |

つまずきやすい点：

- 公式リポジトリ（thuml/Transolver）は CUDA 前提の書き方（`.cuda()` の直書きなど）。デバイス指定を `mps` に置き換える。
- MPS に未対応の演算が出たら `PYTORCH_ENABLE_MPS_FALLBACK=1` で CPU に逃がせる。使ったときは時間の比較から分けて記録する。

最初に縮める設定：

| 項目 | 推奨 |
|---|---|
| 学習時の点数 | 1ケースあたり 16k〜32k 点にランダムに間引く（推論は全点で可） |
| モデル | 層数 4〜6、隠れ次元 128、スライス数 32 程度 |
| データ | AirfRANS の `scarce` タスク（学習200ケース）で動作確認してから `full` へ |
| 精度 | まず fp32（MPS の bf16/AMP は挙動を確認してから） |

## データセット

### AirfRANS（採用）

- 2次元の非圧縮 RANS 計算（Spalart–Allmaras）1000ケース。
- 形状：NACA 4桁・5桁系の翼型をパラメータで変えている。
- 気流条件：レイノルズ数 約2〜6×10⁶、迎角 約 −5°〜15°。
- 出力：u、v、p、乱流粘性 νt の場と表面量。専用パッケージ `airfrans` に揚力・抗力係数の評価関数がある。
- 評価用の分割：`full`、`scarce`、レイノルズ数の外挿、迎角の外挿。Transolver の論文でも使われている。

限界：2次元・非圧縮・亜音速のみで、衝撃波を含む遷音速域や3次元効果は扱えない。形状は NACA 系に限られる。

### その他の候補

| データセット | 向いている用途 |
|---|---|
| Geo-FNO の Airfoil（Transolver の標準ベンチマーク） | 小さい構造格子で軽い。遷音速 Euler だが流れ条件は固定。パイプライン確認向き |
| ShapeNet-Car（Transolver 論文で使用） | 3次元の車形状。流れ条件は固定 |
| DrivAerNet++ など | 3次元・大規模。Mac mini では厳しい |

## 次の手順

1. `external/` に Transolver 公式リポジトリを clone し、`Airfoil-Design-AirfRANS` のデバイス指定を MPS に書き換える。
2. `airfrans` パッケージで `data/` にデータをダウンロードして前処理する（生データは VTK 形式、全体で数GB〜10GB程度）。
3. 縮小設定で `scarce` タスクを学習し、表面圧力から求めた揚力・抗力係数を CFD 値と比較する。
4. 結果を見て `full` タスクや外挿タスクに広げる。
