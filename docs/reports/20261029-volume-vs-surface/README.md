# 体積場も学習させた場合の表面の精度（計画）

作成日: 2026-10-29。状態: **VOL-01 は実行済み（2026-10-30）。VOL-02・VOL-03 は未実行**。当初は[表面だけの Cp・Cf 予測](../20261029-surface-cp-cf/README.md)の結果を見てから始める予定だった。10月30日に、AirfRANS での学習と評価の流れと実際の時間を先に確かめるため、VOL-01 を SURF-01 より前に実行すると決めた（[時間の見積もり](../20261030-airfrans-step-time/README.md)を参照）。

## 目的

AirfRANS の公式コード（体積場と表面を同時に学習する）で Transolver を学習させ、表面の Cp・Cf と Cl・Cd の精度を、表面だけで学習したモデルと同じテストケースで比べる。問いは「体積場の情報が表面の予測を良くするか」。

公式の設定で動かすので、論文と比べられる設定に移る足がかりにもなる。

## 位置づけ

- 公式の指標（体積場・表面場の誤差、Cl・Cd の誤差、順位相関）も記録する。ただし、論文の数値と並べてよいのは公式と同じモデルの大きさとエポック数の実行（VOL-03）だけ。縮小した実行は縮小と明記する。
- データの分割は AirfRANS 公式の分割を使う。
- 予測は CFD の代わりになる検証済みの解ではない。

## 取得するもの

表面だけの計画と同じ（Transolver 公式リポジトリ commit `75e0f6764380` の `Airfoil-Design-AirfRANS/`、`airfrans` 0.1.5.1、AirfRANS データセット）。

## 公式コードへの変更

- `.cuda()` の直書きと `cuda:0` の選択を、`mps`（使えなければ `cpu`）を選ぶ装置指定に置き換える。
- それ以外の設定は変えない。変更は上流のコードなので、このリポジトリには入れない。変更内容は再現手順に文章で記録する。

10月30日に実際に入れた変更（差分は `local/transolver-mps.diff`、Git 管理外）:

| ファイル | 変更 | 結果への影響 |
|---|---|---|
| `main.py` | 装置を `mps`（使えなければ `cpu`）にする。`.cuda()` を `.to(device)` にする | なし |
| `main.py` | 引数 `--n_hidden`、`--n_layers`（既定は公式の256、8）と `--nb_epochs`（`params.yaml` の値を上書き）を加える | 縮小した実行のためだけ。既定のままなら公式と同じ |

## VOL-01 の結果

評価は公式の評価（`main.py` の `--score 1` と同じ処理）で、テストは `full_test` の200ケース、全点。値は [VOL-01-score.json](VOL-01-score.json)（公式の `score.json` そのまま）。

| 指標 | 値 |
|---|---|
| 体積場の MSE（正規化後）: u、v、p、νt | 0.0882、0.0564、0.0277、0.0693（平均 0.0605） |
| 表面の MSE（正規化後）: p | 0.0781 |
| Cl の相対誤差 | 平均 0.336、中央値 0.093 |
| Cd の相対誤差 | 平均 23.1、中央値 23.1 |
| 順位相関（Spearman）: Cl、Cd | 0.980、−0.027 |

- 表面の u、v、νt は、公式の評価が壁の条件（0）で上書きするので誤差は0になる。
- Cl の平均は、Cl が0に近いケースで相対誤差が大きくなるため、中央値より大きい。
- **Cd は使えない。** 予測の Cd は 0.074〜0.59（中央値 0.25）で、CFD の 0.0072〜0.035（中央値 0.011）のおよそ20倍になっている。原因は下の「Cd の内訳」で調べた。
- 公式の評価が出す表面の p と壁面せん断応力の点ごとの相対誤差（`mean_rel_p` 8.37、`mean_rel_wss` 354・431）は、正解が0に近い点で値が大きくなるので、比較には使わない。

学習の途中の検証の MSE（検証20ケース、32,000点に間引いて20回の平均）:

| エポック | 体積場 | 表面 |
|---|---|---|
| 0 | 0.794 | 0.327 |
| 49 | 0.303 | 0.0846 |
| 99 | 0.242 | 0.0976 |
| 149 | 0.0910 | 0.0164 |
| 199 | 0.0675 | 0.0075 |

最終エポックの学習の損失は、体積場 0.0571、表面 0.0025。

### Cd の内訳（2026-10-30）

公式の評価と同じ推論と積分で、Cl・Cd を圧力成分と摩擦成分に分けて求めた。あわせて、壁からの距離ごとに速度の誤差（一様流の速さで割った値の二乗平均平方根）を求めた。テスト200ケースすべて。ケースごとの値は [VOL-01-cd-components.csv](VOL-01-cd-components.csv)、スクリプトは [diag_cd_airfrans.py](diag_cd_airfrans.py)。

正解の圧力成分と摩擦成分を足した Cd は、公式の評価が出した正解の Cd と 1e-16 の差で一致した。推論は乱数で点を間引くので、予測の値は公式の評価の実行とは少し違う（種は0に固定）。

| 量（200ケースの中央値） | 正解（CFD） | 予測 |
|---|---|---|
| Cd の摩擦成分 | 0.0071 | 0.25（正解の22〜72倍、中央値36倍） |
| Cd の圧力成分 | 0.0034 | 0.0070（−0.081〜0.065） |
| Cl の圧力成分 | 0.74 | 0.76 |
| Cl の摩擦成分 | 0.0001 | −0.010 |

| 壁からの距離（翼弦長 = 1） | 1ケースあたりの点数（中央値） | 速度の誤差（中央値） |
|---|---|---|
| 0〜1e-4 | 21,590 | 0.36 |
| 1e-4〜1e-3 | 29,620 | 0.18 |
| 1e-3〜1e-2 | 33,340 | 0.15 |
| 1e-2 以上 | 94,820 | 0.055 |

わかったこと:

- Cd の誤差の大部分は摩擦成分から来る。壁に一番近い点は壁から約2e-6の距離にあり、そこでの速度の誤差は一様流の速さの3割を超える。公式の評価は、この速度の差を壁からの距離で割った勾配から壁面せん断応力を求めるので、摩擦が数十倍に膨らむ。
- 圧力成分も使える精度ではない。誤差の絶対値の中央値は 0.011 で、正解の Cd 全体（中央値 0.011）と同じ大きさになる。摩擦がもし正しくても、Cd は予測できていない。
- Cl はほとんどが圧力成分で、その予測は正解に近い。Cl の誤差が小さく順位相関が高いのはこのため。
- 縮小したモデルで `scarce` を200エポック学習しただけの結果なので、公式の大きさと `full` で同じことが起きるかは確かめていない。

## 評価

表面の量は、表面だけの計画と同じ定義で計算する。

| 指標 | 内容 |
|---|---|
| 表面の Cp | 予測した p の表面の点の値から計算する |
| 表面の Cf | 予測した速度場から `wallshearstress(reference=False)` で τw を計算し、表面だけの計画と同じ接線で Cf にする |
| 力係数 | `force_coefficient(reference=False)` の Cl、Cd（圧力成分と粘性成分）。自作の積分の結果とも一致を確かめる |
| 公式の指標 | 公式 `main.py` の評価（体積場・表面場の誤差、Cl・Cd の誤差、順位相関） |

比べ方: 同じテストケースで、VOL-01 と SURF-01、VOL-02 と SURF-02 の Cp・Cf の相対L2誤差と、Cl・Cd の誤差を並べる。

Cf は速度場の勾配から求めるので、体積場の予測が壁近くでずれると Cf の誤差が大きくなりうる。表面だけのモデルは Cf を直接予測するので、この点で条件が違うことを結果に書き添える。

時間とメモリ（1エポックの時間、推論時のピークメモリ）は精度とは別の表に記録する。推論は全点（約18万点/ケース）で行うので、メモリが足りるかを VOL-01 で確かめる。

### 実行したコマンド

`external/Transolver/Airfoil-Design-AirfRANS/` で実行した。

```sh
# 学習（VOL-01）。最後に学習曲線の図で止まるが、モデルはその前に保存される
caffeinate -i /usr/bin/time -l python main.py --model Transolver -t scarce \
  --n_hidden 128 --n_layers 5 --nb_epochs 200 --score 1 \
  --my_path ../../../data/airfrans/Dataset --save_path ../../../results/airfrans/VOL-01

# 評価だけを別に実行（main.py の --score 1 の処理と同じ）
MPLBACKEND=Agg caffeinate -i /usr/bin/time -l python ../../../local/score_airfrans.py scarce \
  ../../../data/airfrans/Dataset ../../../results/airfrans/VOL-01/scarce/Transolver/model \
  ../../../results/airfrans/VOL-01/scores
```

`local/score_airfrans.py`（Git 管理外）は、公式 `main.py` の評価部分を抜き出したもの。学習データから正規化の係数を `main.py` と同じ手順で作り直し、保存したモデルを読み込んで `utils.metrics.Results_test` を呼ぶ。今後は、学習のときから `MPLBACKEND=Agg` を付けて走らせる。
